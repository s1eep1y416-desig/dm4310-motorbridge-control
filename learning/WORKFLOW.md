# 学习与开发工作流

本文件依 [AGENTS.md](../AGENTS.md) 及原文 §17、§18、§26–29 细化执行，不另立主流程。

## 开发、教学与阶段验收

工程开发：读取项目 → 明确需求 → 提出方案 → 实施 → 验证 → 代码审查 → 文档更新 → 学习考核。
教学：理论讲解 → 任务设计 → 学习者实现 → 提示与纠错 → 测试 → 代码审查 → 复盘。
阶段验收：理论学习 → 独立开发 → 实验验证 → 代码审查 → 理论考核 → 文档检查 → 阶段验收。

原文允许多对话承担工程开发、理论学习、代码审查、实验分析、故障排查、知识库维护、阶段考核。
职责可以合并；没有强制七个对话或固定 01–07 启动顺序。用户已授权在当前聊天定时执行，详见 [定时学习安排](SCHEDULE.md)；不自动创建聊天或向其他聊天发消息。

## 每日任务

默认每天约两小时，每次一个核心任务：A 核心理论；B 开发实践；C 测试或实验；D 3–5 道思考题；E 代码审查；F 知识沉淀。
可以提前设计问题；学习者回答后再评价。代码审查基于实际提交；工程方案可在实现前记录，结果与结论必须有实际证据。
理论 25 分钟、实践 60 分钟、验证 20 分钟、记录 15 分钟只是分配建议，不是原文硬性时间表。
未完成时记录原因和当前状态，下次优先继续；不因日期变更跳过验收。

## 文件职责

每日过程归 learning/daily/，包括日期、阶段、目标、完成内容、理论、修改文件、测试、问题、未完成与下一步。
通用理论归 knowledge/，项目设计归 engineering/，实验归 experiments/，故障归 troubleshooting/，考核归 learning/assessments/。
各类使用相对链接关联，已有知识优先引用；不强制合并理论/设计。
2026-10-09 已按用户要求清空每日任务及配套材料。随后按用户要求设置从 2026-10-10 开始的定时学习安排；旧任务保持删除，新任务在首次晨间运行时生成。

## 状态与证据

任务池使用 Backlog → Ready → In Progress → Submitted → In Review → Done，另用 Blocked/Deferred 记录原因；这是任务管理细化，不替代原文阶段状态。
阶段状态严格使用 Not Started / In Progress / Pending Hardware / Failed / Passed。
编程任务须有用户代码、测试和解释；文档盘点按其真实提交物复核，不编造代码审查。
阶段评分与必需实验按 roadmap/milestones.md；缺必需硬件验证不得 Passed。

任务开始、提交、验收时分别更新实际状态和证据；只维护受影响文件，延期保持原任务 ID。
