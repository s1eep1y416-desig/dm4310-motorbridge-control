## 下发与续做

1. 一天最多一个核心任务，默认约两小时；较大任务分多次学习单元完成。
2. 未完成优先续做，保留任务 ID、阻塞原因、恢复条件及前次记录链接。
3. 依 [每日任务模板](../templates/daily-task.md) 生成 `learning/daily/YYYY-MM-DD-任务ID.md`；复盘使用 `YYYY-MM-DD-weekly-review.md`。日期采用北京时间。
4. 任务卡提供理论依据、实践要求、验收方法和 3–5 道思考题；等待用户实现与回答。通用理论和项目设计分别归 knowledge/、engineering/。
5. 新下发任务为 Ready；用户实际开始、提交、复核通过后再按流程更新状态。日程到期不能证明完成。
6. 同一天、同一任务和时段只处理一次，保护用户已写内容。延迟运行只补办最近一个未处理时段，不批量补发。
7. 硬件阻塞时保留阻塞任务；可安排前置知识已具备的独立理论或离线补练，不越过硬件验收。
8. 每次下发由助手确定具体文件名，逐项说明文件夹、文件名、完整路径、新建/修改/阅读、用途和本次应写内容，并区分助手已提供的材料与学习者要写的文件。给出必要的目录/文件创建命令、VS Code 打开位置、验证命令和执行目录；续做明确修改哪个已有文件。不让学习者自行猜目录或命名，不覆盖已有内容，不提前建立未来模块。

## 晚间检查与周复盘

检查实际文件和用户提交，不要求先 Git 提交。没有代码提交不做代码审查，没有答题不评学习掌握；盘点类任务按文档提交物复核。

分开记录实现、静态检查、Mock、仿真、真实硬件实验和用户理解。未完成原因不明时写待反馈；只在新证据或状态变化时更新记录。阶段评分与必要实验严格依 milestones.md。

周复盘替代当天新开发任务。每月第一次周六复盘顺带核对阶段排期、事实版本、文档链接与重复知识；不因日期到期自动晋级。

晨间交付简短安排与任务卡链接；晚间仅对新完成证据、新阻塞、失败或需要用户行动的情况通知。同一未提交状态没有变化时不重复催促。
