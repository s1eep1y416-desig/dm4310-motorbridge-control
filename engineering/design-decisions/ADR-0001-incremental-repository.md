# ADR-0001：独立仓库与渐进开发

- 日期：2026-10-09。
- 状态：采用；用户已明确选择“建立新仓库，旧项目作为参考”。
- 背景：用户要求依据 V1.2 PDF 建立长期开发仓库和学习任务。已有旧项目包含已暂存改动；另有未提交同名治理草稿。
- 需求：可追溯的学习路线、保留既有有效工作、逐步建立实际能力。
- 方案：直接修改旧项目；接管另一草稿；在本任务 outputs 下建立独立仓库并记录关联。
- 决定：采用独立仓库，不迁移旧源码、不继承完成状态、不关联既有同名远端。
- 原因：用户明确选择新仓库，且旧项目有未提交状态；新仓库便于独立检查与后续明确迁入。
- 影响：存在多个目录，README 和基线说明明确本次交付的位置。后续确认主仓库后再收敛，不能双份同时维护同一事实。
- 代码策略：先建立文档和检查工具。S1-003 开始时建立 actuator/safety 的最小所需部分与 pyproject；后续模块在实际阶段建立。
- 备选代价：直接重构旧项目可能破坏暂存改动与导入；一次生成全部模块增加空壳维护。
- 回退：本次仅新增独立目录，可由用户后续选择保留、迁入或归档；不删除其他项目。
- 验证：仓库检查、来源映射和旧项目状态复核；没有业务功能或硬件验证。
