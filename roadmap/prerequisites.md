# 前置条件与分支路线

## S1 开始即可做

能读 Python 函数、异常、上下文管理和基本测试；能解释十六进制、rad 与 rad/s；能检查 Git 状态。
不足部分安排局部补课；直接从 MotorBridge 的对象和状态显示练习开始，连接/ID 与环境资料在相关任务中补齐，不把底层通信课程前置到第一天。
以后开始相应阶段时，按 [PROJECT.md](../PROJECT.md) 核对事实并建立证据，不默认用户已经掌握或完全不会。[S1-001](../learning/daily/2026-10-10-S1-001.md) 已于 2026-10-11 完成；下一任务为 S1-002。

## 真实实验前

设备型号、固件、减速比、协议和 SDK 适配已对应；ID、通信方式、供电、机械固定/负载、零点/方向/行程可追溯。
根据实际实验确认电气/机械急停、失电与通信异常后的行为，以及操作者可达的停止方式。
实验步骤、有效范围、停止条件和恢复方法已记录；当前实验有明确操作授权。
数据读取也可能发送查询帧；SDK 构造器可能打开设备，不能将普通 Python 导入/构造假定为离线操作。
对缺失项写待确认；这些条件只阻塞相关真实实验，不阻塞文档、源码阅读和 Mock。

## S3/S4 前

确认实际 Ubuntu 主机或受支持开发环境、架构、Python/C++、ROS 2 发行版、ros2_control、SDK ABI 和构建工具的组合。
发行版在实际环境核对后选定；资料索引中的 Jazzy 页面只是示例资料入口，不代表本项目已选择 Jazzy。
确认 C++ Hardware Interface 与 MotorBridge C ABI/其他可维护传输接口的兼容性；若需进程桥接，先写时延、故障传播、控制权和生命周期 ADR。
不要把 Python ROS 节点包装等同标准 ros2_control Hardware Interface。

## S5/S6 前

第二电机、ID 分配、供电容量、总线拓扑和双关节固定/行程已核对。
补齐矩阵、坐标变换、三角函数、数值误差与导数；URDF 关节顺序和实际电机映射一致。
二维二连杆算例可先离线学习，但其长度/关节约定不能直接用于真实机构。

## S7/S8 前

质量、质心、惯量、重力方向、关节方向、传动和输出力矩定义有证据；存在安全的机械支撑/限位方案。
第三关节、三维模型和控制任务维数确定；三自由度不等于任意六维位姿控制。
非冗余系统的零空间控制先通过合适维数的数学/仿真任务学习，不强行宣称具备额外运动自由度。

## 无硬件或环境受限

优先进行接口设计、合成反馈序列、可控时钟的超时验证、纯数学 FK/IK/Jacobian，以及匹配环境下的 Fake Hardware。
若真实实验已到执行点却缺设备，将该任务标记 Blocked、阶段标记 Pending Hardware，记录缺项和恢复条件。
阶段不能因 Mock 成功而通过真机门槛；可完成的独立学习单元继续推进。
